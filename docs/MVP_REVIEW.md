# MVP review

## E2E-сценарий

Критический путь MVP проверяется на production Compose:

1. регистрация и повторный вход;
2. создание кампании, вида и каждого типа виджета;
3. редактирование Markdown с optimistic revision;
4. команды таймера, кубиков и трекера боя;
5. режим сессии, `Alt+N`, создание заметки с начальным состоянием;
6. перезагрузка, восстановление снимка и повторное подключение WebSocket.

API-часть сценария автоматизирована в `auth-campaigns.integration.test.ts`. Интерфейсный сценарий
проверяется браузером на production-сборке перед завершением этапа.

## Security

- cookie-сессии не доступны JavaScript; state-changing запросы проверяют `Origin`;
- идентификаторы валидируются как UUID, входные данные — Zod-схемами;
- начальное состояние быстрого виджета повторно проверяется схемой его типа на сервере;
- ответ API не раскрывает stack trace и содержит request ID;
- web и API отправляют `nosniff`, запрет iframe, Referrer Policy и Permissions Policy;
- PostgreSQL находится только во внутренней сети Compose.

Полный CSP для скриптов потребует nonce на каждый запрос. До внедрения nonce политика ограничивает
`frame-ancestors`, `base-uri` и `object-src`, не ломая гидратацию Next.js.

## Accessibility

- все основные операции доступны кнопками и клавиатурой;
- режим сессии имеет доступные названия управления и `aria-keyshortcuts`;
- диалог быстрой заметки объявлен как modal dialog, получает фокус и удерживает его по Tab;
- для клавиатурного фокуса задан контрастный индикатор;
- при `prefers-reduced-motion` анимации практически отключаются.

## Performance and resilience

- web запускается как минимальная standalone-сборка Next.js со сжатием;
- доска не перезапрашивается чаще десяти секунд без события;
- WebSocket использует ограниченную экспоненциальную задержку повторного соединения;
- возврат сети и видимости вкладки принудительно восстанавливает актуальный REST-снимок;
- команды виджетов выполняются на сервере с optimistic revision.

## Operations

- production Compose содержит healthcheck для каждого постоянного сервиса;
- профиль `maintenance` создаёт сжатый PostgreSQL dump в `backups/`;
- seed идемпотентно создаёт нейтральную демонстрационную кампанию со всеми четырьмя инструментами;
- восстановление выполняется только в остановленное на запись приложение и после свежей копии.
