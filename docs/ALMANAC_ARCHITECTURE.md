# Альманах кампании

## Решение и границы

Альманах — новое пользовательское имя существующей библиотеки знаний. Каждая кампания
уже имеет изолированный набор `LoreEntry` по `campaignId`, поэтому перед тестовой игрой
не создаётся второй параллельный модуль и не меняются существующие URL `/lore`.

Альманах решает четыре задачи:

1. мастер быстро находит подготовленные сведения внутри конкретной кампании;
2. записи видны как понятные разделы, а не как один длинный список;
3. один материал можно пометить важным независимо от его типа;
4. опубликованные материалы появляются только у разрешённых игроков.

Альманах не является бестиарием или справочником правил. Бестиарий, статблоки и
Encounter Lab остаются отдельным следующим контекстом и могут ссылаться на записи
Альманаха, но не подменяют их.

## Информационная модель

На первом срезе сохраняется `LoreEntry`, а поле категории расширяется:

```ts
type AlmanacEntryKind =
  'GENERAL' | 'CLUE' | 'FACT' | 'MAP' | 'PERSON' | 'PLACE' | 'EVENT' | 'ITEM' | 'HANDOUT';

type AlmanacEntry = {
  // существующие поля LoreEntry
  kind: AlmanacEntryKind;
  isPinned: boolean;
};
```

В коде первого среза `kind` продолжает передаваться как совместимое поле `category`.
Переименование контракта и REST-маршрутов откладывается, чтобы не тратить время перед
игрой на механическую миграцию без пользовательской пользы.

`Важное` — не тип записи, а сохранённое представление `isPinned = true`. Благодаря этому
карта, персонаж или зацепка одновременно остаются своим типом и попадают в раздел
«Важное» без копирования. Тип записи взаимоисключающий; доступ и важность — независимые
признаки.

Начальные разделы Альманаха:

- `Все`;
- `Важное` — записи с `isPinned`;
- `Карты` — `MAP`;
- `Зацепки` — `CLUE`;
- `Факты` — `FACT`;
- `Персонажи`, `Места`, `События`, `Предметы`, `Раздатки`;
- `Общее`.

Пользовательские разделы до 18 августа не добавляются. Когда появится подтверждённая
потребность, вводятся `almanac_sections` и `section_id`; текущие встроенные типы остаются
стабильными системными ключами и мигрируют в предсозданные разделы кампании.

## Карты внутри Альманаха

Запись типа `MAP` использует уже существующие защищённые изображения-вложения. В первом
срезе первое изображение является обложкой карточки, остальные показываются в галерее.
PDF не используется как обложка, но остаётся доступным вложением.

Карта Альманаха — знание или исходный материал. Тактическая сцена — отдельная исполняемая
сущность. Позже мастер сможет создать сцену из изображения записи `MAP`, но публикация
записи игрокам и показ фона активной сцены должны оставаться двумя независимыми решениями.

## Доступ и синхронизация

Существующая модель не меняется:

- `OWNER` и `GM` видят черновики и опубликованные записи кампании;
- `PLAYER` видит только `PUBLISHED` с аудиторией `ALL_PLAYERS` либо запись, где он есть
  в `lore_entry_recipients`;
- закрытые записи фильтруются до построения DTO;
- вложение повторно проверяет доступ к записи перед отдачей байтов;
- `campaign.lore.changed` не содержит текст и заставляет перечитать авторизованный
  REST-снимок.

`isPinned` не влияет на доступ: игрок не может узнать о закреплённой закрытой записи.

## Изменения хранения и API

Миграция первого среза:

- добавить значения `CLUE`, `FACT`, `MAP` в `lore_category`;
- добавить `lore_entries.is_pinned boolean not null default false`;
- сохранить все существующие записи без преобразования;
- добавить индекс `(campaign_id, is_pinned)` только если список реальной кампании
  становится достаточно большим; для домашнего теста фильтрация снимка в памяти допустима.

Контракты создания и обновления получают `isPinned`; DTO записи возвращает его всем,
кто уже имеет право видеть запись. REST-маршруты и optimistic `expectedRevision`
сохраняются.

## Интерфейс

Мастер видит:

- заголовок «Альманах» вместо «Библиотека»;
- вертикальные разделы с количеством записей;
- быстрый поиск по названию и тексту внутри выбранного раздела;
- кнопку-звезду «Важное» на карточке и в редакторе;
- галерею обложек в разделе «Карты»;
- прежние настройки черновика и публикации.

Игрок видит тот же Альманах, но только свою отфильтрованную проекцию. Название
«Известное» можно оставить как подзаголовок: «Альманах · Известное вашей группе».

## Исторический объём первого игрового среза — 18 августа 2026

Обязательно:

- новые типы `MAP`, `CLUE`, `FACT`;
- `isPinned` и раздел «Важное»;
- навигация по разделам и счётчики;
- переименование интерфейса в «Альманах»;
- карточки карт с существующими изображениями;
- unit/contract-тесты новых полей и integration-тест отсутствия утечки игрокам.

После игры:

- пользовательские разделы и теги;
- связи между записями;
- отдельное поле обложки;
- полнотекстовый PostgreSQL-поиск;
- перенос карты Альманаха в шаблон тактической сцены.

## Критерии готовности

Срез готов, когда мастер может открыть кампанию, создать карту, зацепку и факт, пометить
любую запись важной, найти её через соответствующий раздел и безопасно опубликовать
всем либо выбранному игроку. После перезагрузки и reconnect разделы и выбранная запись
восстанавливаются без появления закрытых данных у игрока.
