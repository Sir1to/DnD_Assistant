# Fog of Lore

Fog of Lore — self-hosted веб-приложение-компаньон для мастера настольных ролевых
игр. Оно объединит заметки, таймеры, броски и трекер боя на настраиваемой доске,
синхронизируемой между устройствами.

Сейчас реализованы инфраструктурный фундамент и ядро настраиваемой доски:
pnpm-монорепозиторий, Next.js-интерфейс, NestJS API, PostgreSQL/Drizzle, healthcheck,
структурированные логи, Docker Compose и CI, а также регистрация, вход, безопасные
сессии, кампании, виды доски и заметки с Markdown. Виджеты можно перемещать, изменять
в размере, размещать в нескольких видах и синхронизировать между вкладками.

## Архитектура

`apps/web` содержит Next.js App Router и React UI. `apps/api` — NestJS REST/WS backend
и доступ к PostgreSQL через Drizzle. Общие Zod-контракты, чистая domain-логика,
UI-компоненты и конфигурация вынесены в `packages/`.

REST будет использоваться для загрузки/CRUD и восстановления после reconnect,
WebSocket — для событий доски. `WidgetInstance` хранит общее состояние, а
`WidgetPlacement` — положение в конкретном `BoardView`. Подробнее:
[архитектура](docs/ARCHITECTURE.md), [продукт](docs/PRODUCT.md),
[API](docs/API.md), [roadmap](docs/ROADMAP.md).

## Необходимые программы

- Node.js 24 или новее;
- pnpm 11;
- PostgreSQL 18 для локального запуска без контейнеров;
- Docker с Compose v2 для контейнерного запуска;
- Git.

Установка pnpm:

```bash
corepack enable
corepack prepare pnpm@11.9.0 --activate
```

На Windows, если PowerShell блокирует `pnpm.ps1`, используйте `pnpm.cmd` или разрешите
подписанные локальные сценарии согласно политике вашей организации.

## Первый локальный запуск

```bash
cp .env.example .env
pnpm install
pnpm db:migrate
pnpm db:seed
pnpm dev
```

Перед миграцией замените пароли в `.env`. При запуске без Docker укажите в
`DATABASE_URL` адрес вашей PostgreSQL. Web будет доступен на
`http://localhost:3000`, API healthcheck — на `http://localhost:4000/api/health`.

`pnpm dev` запускает web и API параллельно. Для отдельного процесса:

```bash
pnpm --filter @fog-of-lore/web dev
pnpm --filter @fog-of-lore/api dev
```

## Миграции и демонстрационные данные

После изменения `apps/api/src/database/schema.ts`:

```bash
pnpm db:generate
```

Проверьте новый SQL в `apps/api/drizzle`, затем примените:

```bash
pnpm db:migrate
```

Seed требует `DEMO_PASSWORD` длиной не менее 12 символов:

```bash
pnpm db:seed
```

Он создаёт нейтральную кампанию «Пепельный предел» и не содержит лицензируемого
игрового контента.

## Проверки

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm format:check
pnpm migrations:check
```

Integration-тест авторизации, кампаний, полного сценария заметки, optimistic conflict и
изоляции пользователей требует отдельную PostgreSQL-базу в `TEST_DATABASE_URL`:

```bash
pnpm test:integration
```

Тестовая база должна быть отдельной: integration-тесты очищают её таблицы. Для browser E2E
сначала соберите приложения и примените миграции к этой же тестовой базе:

```bash
pnpm test:e2e:install
pnpm build
pnpm db:migrate
pnpm test:e2e
```

В CI PostgreSQL, миграции, integration-тесты и Chromium запускаются автоматически.

## Проверка этапа 2 в браузере

1. Откройте `http://localhost:3000`.
2. Нажмите «Начать» и зарегистрируйтесь; пароль должен содержать не менее 12 символов.
3. В кабинете нажмите «Создать кампанию», заполните название и описание.
4. Убедитесь, что открылась «Мастерская» с видом «Ноутбук мастера» и ролью `OWNER`.
5. Вернитесь к списку кампаний, выйдите и войдите снова.
6. Убедитесь, что созданная кампания сохранилась.

Открытие `/dashboard` без действующей сессии должно перенаправить на `/login`.

## Проверка этапа 3 в браузере

1. Откройте существующую кампанию и нажмите «Редактирование».
2. В каталоге нажмите «+ Добавить» у заметки.
3. Откройте вкладку «Текст», введите Markdown и подождите появления статуса «Сохранено».
4. Откройте «Просмотр» и убедитесь, что заголовки, выделение и списки отрисованы.
5. Перетащите виджет или используйте кнопки `← → ↑ ↓ Ш+ В+`; должен появиться статус
   «Раскладка сохранена».
6. Создайте «+ Новый вид» и добавьте в него уже существующую заметку.
7. Откройте кампанию во второй вкладке: изменения должны появляться без ручной
   перезагрузки, а после краткого отключения сети данные должны восстановиться.

В режиме «Использование» раскладка заблокирована от случайного перемещения.

## Проверка этапа 4 в браузере

1. Откройте кампанию, включите «Редактирование» и добавьте из каталога таймер,
   «Кубики и таблицу» и трекер боя.
2. В таймере выберите обратный отсчёт или секундомер, задайте длительность, запустите,
   поставьте на паузу, продолжите и сбросьте.
3. В кубиках нажмите быстрый `d20`, выполните `2d6+3`, сохраните несколько строк
   случайной таблицы и нажмите «Выбрать».
4. В трекере добавьте игрока и противника с инициативой и HP, начните следующий ход,
   нанесите урон, вылечите участника и завершите бой.
5. Перезагрузите страницу: история, таймер и незавершённый бой должны восстановиться.
6. Добавьте таймер во второй вид доски и откройте оба вида в разных вкладках. Команды
   должны синхронизироваться через WebSocket.

## Проверка этапа 5 в браузере

1. Откройте кампанию и нажмите «На весь экран». Навигация, заголовок и каталог должны исчезнуть,
   а доска — занять всё окно.
2. Нажмите `Alt+N`, введите текст и сохраните. Новая заметка должна появиться внизу текущего вида
   без выхода из режима сессии.
3. Повторно откройте заметку по `Alt+N`, затем проверьте `Tab`, `Shift+Tab` и `Esc`: фокус остаётся
   внутри диалога, а `Esc` сначала закрывает заметку.
4. Выйдите из режима кнопкой в правом нижнем углу или клавишей `Esc`.
5. На время отключите сеть в DevTools, затем включите её: индикатор должен перейти через
   «Подключаемся…» обратно в «Синхронизация включена», а доска — обновиться.

Режим сессии использует Fullscreen API. Если браузер или политика окна запрещает настоящий
fullscreen, интерфейс автоматически остаётся в эквивалентном режиме без панелей внутри вкладки.

## Проверка этапа 6 в браузере

1. Откройте кампанию владельцем и нажмите «Игроки».
2. Создайте одноразовую ссылку, скопируйте её и откройте в приватном окне браузера.
3. Войдите другим аккаунтом или зарегистрируйтесь: после входа Fog of Lore вернёт вас к
   приглашению. Нажмите «Присоединиться к кампании».
4. Пока ни один вид не опубликован, игрок увидит сообщение «Мастер готовит доску».
5. В окне владельца выберите вид и нажмите «Только для мастеров», чтобы кнопка сменилась на
   «Виден игрокам». В окне игрока вид появится автоматически.
6. Убедитесь, что у игрока нет каталога и кнопок управления виджетами. Переключите вид обратно
   в мастерский — он должен исчезнуть у игрока.
7. Повторное открытие использованной ссылки другим аккаунтом должно показать, что приглашение
   уже принято. Активную неиспользованную ссылку можно отозвать в истории приглашений.

## Проверка этапа 7 в браузере

1. Откройте кампанию владельцем и нажмите «Знания» в верхней панели.
2. Создайте материал, выберите категорию и сохраните его как черновик. В аккаунте игрока он
   появиться не должен.
3. Переключите доступ на «Всем игрокам» и сохраните. Материал автоматически появится на экране
   «Известное» у подключённого игрока без перезагрузки страницы.
4. Создайте вторую раздатку, выберите «Выбранным игрокам» и отметьте одного участника. Другой
   игрок не должен увидеть её даже по прямой ссылке API.
5. Проверьте Markdown через вкладку «Просмотр», поиск по тексту и фильтр категорий.
6. Снимите публикацию, выбрав «Черновик»: материал должен исчезнуть у игроков.

## Encounter Lab

В кампании откройте «Справочник» → `Encounter Lab`. Добавьте группы персонажей одного или
разных уровней, затем найдите противников в бестиарии по названию, типу или CR. Выбранное
существо переносит в расчёт своё имя, CR и XP; собственный статблок по-прежнему можно ввести
вручную. Лаборатория показывает суммарный XP противников и границы низкой, средней и высокой
сложности по SRD 5.2.1. Старый множитель за число существ из правил 2014 года не применяется.
XP за одно существо остаётся редактируемым для CR 0 и пользовательских статблоков.
Если в кампании уже есть активная боевая сцена, `OWNER` или `GM` может нажать
«Перенести на поле». Все SRD-копии получат свои HP, КД, скорость, размер и
независимое боевое состояние; после успешной расстановки откроется поле боя.

Отдельный раздел «Бестиарий» содержит 322 нормализованных статблока SRD 5.2.1. Список
фильтруется без загрузки тяжёлых описаний, а полный статблок запрашивается только после выбора
существа. Исходный текст сохранён на английском; источник и лицензия CC BY 4.0 показаны в UI.

Поле поиска в верхней части «Справочника» работает во всех разделах и одним запросом проверяет
существ, заклинания, предметы и правила. Результаты сгруппированы по типу и ранжируются по
совпадению с названием; выбор открывает найденную запись в соответствующем разделе. Поиск
использует только лёгкий каталог существ, поэтому полные 322 статблока не попадают в web bundle.

Предупреждения отдельно отмечают противника с CR выше максимального уровня группы и состав,
где существ больше двух на персонажа. Это сигналы для мастера, а не автоматический запрет:
особые способности, местность, внезапность и ресурсы персонажей по-прежнему нужно оценивать
вручную.

## Быстрое создание боевой карты

1. Откройте кампанию с ролью `OWNER` или `GM` и перейдите в «Поле боя».
2. На пустом столе нажмите «Создать карту быстро».
3. Выберите местность, размеры, форму, стартовые зоны и параметры столкновения. Любой
   необязательный вопрос можно пропустить — сервер применит понятное значение по умолчанию.
4. На шаге «Проверка» сохраните показанный seed, если вариант нужно будет повторить, или
   нажмите «Перемешать вариант».
5. Нажмите «Создать черновик». Карта не запускает бой автоматически: все враги, препятствия,
   стартовые маркеры и объекты остаются редактируемыми. Генератор сразу назначает им фон,
   токены, материалы препятствий и окружение из встроенного стартового набора.

В мастерской у токена, препятствия или объекта можно открыть «Встроенную библиотеку»,
отфильтрованную по местности и типу, и заменить автоматически выбранный вариант. Системные
ассеты доступны только для чтения и сохраняются стабильным ID; пользовательские JPEG/PNG/WebP
и GIF окружения по-прежнему загружаются отдельно через Альманах. Карточка набора показывает
его версию, источник и лицензию.

Если в кампании уже есть текущая сцена, сначала сохраните её при необходимости и нажмите
«Сбросить текущую сцену».

## Перенос боевых пресетов

В панели «Сохранённые персонажи» кнопка `JSON` выгружает пресет в формате v1, а
`Импорт JSON` добавляет такой файл в текущую кампанию. Внутренние ID и назначенный игрок не
переносятся. JPEG/PNG/WebP-изображение токена включается в файл, если оно не превышает
512 КиБ и 4096×4096; при импорте оно проходит повторную проверку и попадает в приватный
черновик Альманаха. Если пресет использует встроенный токен, JSON переносит его стабильный
`systemAssetId` без встраивания файла.

## Портрет и размещение героя

В разделе «Персонажи» нажмите на квадрат портрета, выберите JPEG/PNG/WebP и настройте положение
кадра и приближение. Браузер отправит только готовый квадрат 512×512. На поле боя откройте
«Сохранённые персонажи», выберите лист и нажмите «Поставить героя». Это не независимый пресет:
участник получает реальную связь с листом, его владельца, текущие/временные HP, состояния,
КД, скорость, класс, вид и портрет. Один лист нельзя поставить на одну сцену дважды; связь и
изображение сохраняются при создании и открытии именованного снимка боя.

## Docker Compose

Скопируйте `.env.example` в `.env`, обязательно замените `POSTGRES_PASSWORD` и
установите `WEB_ORIGIN`.

```bash
docker compose build
docker compose up -d
docker compose exec api pnpm db:migrate
docker compose exec api pnpm db:seed
docker compose ps
```

PostgreSQL не публикуется на хост. Web и API по умолчанию привязаны к `127.0.0.1`.
Чтобы включить пример Caddy:

```bash
docker compose --profile proxy up -d
```

Укажите `FOG_OF_LORE_DOMAIN` и публичный `WEB_ORIGIN` для HTTPS. Caddy автоматически
проксирует `/api`, `/socket.io` и web.

Остановка без удаления данных:

```bash
docker compose down
```

Не используйте `docker compose down -v`, если хотите сохранить базу.

## Обновление

```bash
git pull --ff-only
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm build
```

Для Compose:

```bash
git pull --ff-only
pnpm release:build
docker compose up -d
docker compose exec api pnpm db:migrate
```

`release:build` передаёт version, короткий Git commit и UTC-время в API и web. После
успешной сборки он сохраняет JSON-отчёт в игнорируемом каталоге `deploy-reports/`.
Текущая сборка видна в навигации приложения и в поле `build` ответа `/api/health`;
незакоммиченные исходники получают суффикс `+dirty` в интерфейсе.

Перед обновлением сделайте резервную копию.

## Резервное копирование PostgreSQL

Рекомендуемый вариант для Compose создаёт архив с UTC-временем в каталоге `backups/`:

```bash
docker compose --profile maintenance run --rm backup
```

Создание сжатого архива:

```bash
docker compose exec -T postgres pg_dump -U fog_of_lore -d fog_of_lore -Fc > fog-of-lore.dump
```

Храните архив вне сервера приложения и периодически проверяйте восстановление.

Восстановление в пустую базу:

```bash
docker compose exec -T postgres pg_restore -U fog_of_lore -d fog_of_lore --clean --if-exists < fog-of-lore.dump
```

Операция заменяет существующие объекты: сначала сделайте свежую копию и остановите
запись в приложение.

## Типичные ошибки

- `npm.ps1/pnpm.ps1 cannot be loaded`: вызывайте `npm.cmd`/`pnpm.cmd` либо настройте
  PowerShell ExecutionPolicy.
- `DATABASE_URL is required`: создайте `.env` и проверьте, из какого каталога
  запускается команда.
- `ECONNREFUSED 5432`: PostgreSQL не запущена или hostname должен быть `postgres`
  внутри Compose и `localhost` вне него.
- `Request origin is not allowed`: `WEB_ORIGIN` должен точно совпадать со схемой,
  доменом и портом браузера.
- API healthcheck красный: проверьте `docker compose logs api postgres` и миграции.
- порт занят: измените `WEB_BIND_ADDRESS`/порт публикации либо остановите конфликтующий
  сервис.
